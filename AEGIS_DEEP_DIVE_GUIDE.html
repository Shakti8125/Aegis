Part 1: The Core Problem Statement

First Principles Formulation

What is a Cloud Infrastructure Incident?

Imagine an online application like Amazon or Swiggy. When a user clicks "Buy Now", their request doesn't hit a single monolithic computer. Instead, it travels across dozens of interconnected microservice applications:

[User Mobile App] ──> [API Gateway] ──> [Order Service] ──> [Payment Service] ──> [Database] │ └──> [Inventory Service]

If Payment Service experiences a memory leak and crashes, the Order Service waits for a response and times out. Requests queue up in memory, causing Order Service to run out of RAM and crash as well. This domino effect is called a Cascading Failure.

Deconstructing the Problem from First Principles

1. Topological Graph Structure

Software applications are non-linear graphs, not flat tables. A cluster contains $N$ services, $M$ dependencies, $P$ pods, and $K$ nodes with continuous multi-variable metrics.

2. Cascading Temporal Dynamics

Failures propagate through time and dependency channels. A crash at node $A$ at time $t$ manifests as elevated latency at node $B$ at time $t+k$.

3. Partial Observability

Microservice instances only observe their own local ingress and egress telemetry. No single component has instant complete visibility without aggregation overhead.

4. Human Cognition Bottleneck

Human engineers take 15–45 minutes to parse noisy log streams and query metrics during outages. Downtime costs modern enterprises over $5,000/minute.

Why Traditional Approaches Fail

  • Static Threshold Alerts (e.g., "Alert if CPU > 80%"): Cause alert storms. 50 alerts fire at once during a cascade, obscuring the root cause.
  • Hardcoded Scripts: Fail when clusters autoscale dynamically or when multi-point failures occur.
  • Unconstrained LLM Prompts: Suffer from hallucinations and lack formal mathematical guarantees required for production control loops.

Part 2: Technologies & Algorithms Explained

Learner's Breakdown

1. Infrastructure Layer: Kubernetes & Microservices

Container

A lightweight, isolated package containing application code and all binary dependencies so it runs predictably anywhere.

Pod

The smallest execution unit in Kubernetes hosting one or more co-located containers.

Service

A logical grouping of pods that exposes a single network endpoint (e.g., payment-service).

PettingZoo

Python standard library for Multi-Agent Reinforcement Learning environments (ParallelEnv API).

2. Knowledge Representation: Property Graphs & Neo4j

Traditional SQL databases store data in flat tables requiring expensive multi-table JOINs. A Property Graph models infrastructure directly as entities (Nodes) connected by directed relationships (Edges) with dynamic metric properties: 

// Neo4j Cypher Real Ingestion Example
MERGE (s:Service {id: $service_id})
SET s.health = $health, s.p99_latency_ms = $latency, s.error_rate = $error_rate
MERGE (p:Pod {id: $pod_id})-[:BELONGS_TO]->(s)

3. Deep Learning on Graphs: Graph Neural Networks (GNNs) & GraphSAGE

Standard Deep Learning (MLPs/CNNs) expects fixed input dimensions. Because Kubernetes clusters scale dynamically, Aegis uses GraphSAGE, an inductive GNN that learns neighborhood aggregation functions:

$$h_v^{(k)} = \sigma \left( W \cdot \operatorname{AGGREGATE}_k \left( \{ h_u^{(k-1)}, \forall u \in \mathcal{N}(v) \} \right) \right)$$

When a service scales from 2 to 20 pods during a flash sale, GraphSAGE immediately computes new vector embeddings without requiring neural network retraining.

4. Decision Making: Multi-Agent RL & MAPPO (CTDE)

In a cluster with 12 microservices, a single centralized brain leads to a massive action space ($6^{12} \approx 2.17 \times 10^9$ choices per step!). Aegis assigns a local agent to each microservice using Centralized Training with Decentralized Execution (CTDE):

Training Phase (Centralized Critic)

The centralized Critic network inspects the global cluster state vector $Z_{\text{global}}$ to evaluate overall system value $V(S)$.

Runtime Phase (Decentralized Actors)

Each microservice Actor head inspects only its local node vector $Z_{\text{local}}$ to select actions (`RESTART`, `SCALE_UP`, `ISOLATE`) in milliseconds.

5. Safety & Explanation: Agentic LLMs & Guardrails

Deterministic Safety Veto

Proposed RL actions pass through a deterministic rule supervisor before execution, blocking dangerous actions during maintenance windows.

Fact-Grounded LLM Narrator

Gemini/Ollama models generate natural language post-mortems strictly constrained to cite verified graph telemetry facts.
